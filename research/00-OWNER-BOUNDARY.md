# 00 — OWNER / BOUNDARY

## Harness owner contract

Harness owns **bounded Agent Run mediation**: the cut-relative structures required to mediate an Agent's bounded Run, TaskEpisode, OperationalContextFrame, Invocation lineage, selection/control state, evidence exposure, and related boundary crossings without annexing the truth owned by the systems being mediated.

Harness is not a universal substance, global controller, domain truth owner, normative authority, network substrate, Runtime executor, Human cognition owner, or Host Task owner.

The strongest owner-native center is formed by Foundation Families A, B, C, and I. Family D is mixed native/bridge. Families E, F, G, and H are intentionally bridge-heavy.

## Host boundary — canonical wording

Current mainline wording is deliberately narrow:

- **Host owns durable Host Task continuity plus Host Journal/CAS/fencing/handoff authority.**
- **Persistent purposive coordination is a derived / cross-owner reality, not Host-exclusive ontology.**
- **Harness owns bounded Agent Run / TaskEpisode / Context / Invocation / control mediation.**
- **CompletionProposal != Host Task completion.**

A Harness Run may produce a candidate completion result or `CompletionProposal`; Host or another caller/domain authority separately decides whether its own Task is complete.

## Ordivon Normative boundary

Authority, governance, permission, obligation, legitimacy, due process, remedy, finality, and policy-lineage vocabulary inside HaF11/12/31/34/38–43/47/49 does not make Harness the owner of normative truth.

Harness may mediate externally grounded authority/policy/commitment/process state and preserve evidence about it. **Ordivon Normative owns constitutive/normative admission and consequence semantics** for the corresponding normative claims. Legitimacy, obligation correctness, entitlement, fairness, remedy correctness, and normative finality must therefore remain owner-preserving bridges.

## Runtime boundary

Runtime owns Workspace / Job / Attempt / process and physical execution truth. Harness owns bounded Run/Task/Context/Invocation/control mediation, admitted intent/fence/receipt binding, and the semantic separation of selection, admission, dispatch, effect, result, and completion claims.

HaF6,8,14–19,24,36,37,48,54,55,58–61 may consume or mediate Runtime facts; they do not replace Runtime ontology.

## Network boundary

Network owns cross-locus capability/transport/path/service structure and forwarding/reachability realization where applicable. Harness may mediate distributed/federated operation through HaF18–21,26,40,46,56,59–61 without owning the network substrate.

## Human boundary

Human owns human cognition, motivation, phenomenology, social-human organization and other Human-native structures. HaF13/14 explicitly consumed Human HF18/HF19, and HaF26/41/44/45/46/50 touch human/social/cognitive regimes. Harness owns only the externalized interaction/control/evidence mediation at the Harness cut.

## World and domain-owner boundary

World/Reality and specialist domain owners retain external reality and domain truth. Observation, representation, evaluation, evidence, references, and results inside Harness are claim-/cut-/scope-relative mediation objects. Persistence or representation inside Harness never promotes an external claim into truth.

## Engineering boundary

Product `README.md`, `ARCHITECTURE.md`, Python classes, SQLite schemas, CLI surfaces, provider adapters, Runtime clients, tests and current implementation contracts are downstream Engineering Consumption. They may instantiate or consume research constraints; they are not upstream proof of HaF identity or Foundation standing.
