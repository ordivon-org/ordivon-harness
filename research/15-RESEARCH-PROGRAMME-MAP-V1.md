# 15 — HARNESS RESEARCH PROGRAMME MAP v1

This map turns the frozen HaF corpus into long-lived research programmes. Programmes are **research directions**, not new Foundations, numbering tiers, owner transfers or a preselected roadmap.

## Programme A — Agent–External Boundary Semantics

**Question:** What constitutes the operational cut between Agent and external reality, and how do reference, capability placement and exposure change when that cut changes?

Primary existing substrate:

- Family A — Boundary, Agency & External Mediation.
- HaF0,1,2,25,30,51,54,56.
- Supporting spine roles: Reference, FunctionalPlacement, BoundaryExposure.

Established basis:

- Cut Relativity.
- Harness as mediation rather than protected substance.
- Reference != referent truth.
- Boundary exposure != capability ownership.
- Functional placement is operation-relative rather than intrinsic to a capability.

Open depth questions include cut migration, identity across boundary reconfiguration, operationally equivalent exposure surfaces, and multi-Agent/federated cuts.

## Programme B — Operational Epistemics

**Question:** How does externally grounded state become a decision-sufficient, provenance-aware operational context for an Agent without collapsing observation, retention, representation, history and cognition?

Primary existing substrate:

- Family B — Epistemic Ingress, Representation & External State.
- HaF3,4,5,9,22,35.
- Family I ContextFrame work via HaF53.
- Family D evidence dependencies where epistemic claims cross into assurance.

Established basis:

- RepresentationOrEvidence != Truth.
- Observation != Retention.
- History != Cognition.
- uncertainty has no universal scalar representation.
- distinguishability/diagnosis and external epistemic-state revision are typed and scope/provenance relative.

High-value open questions include Context Equivalence, decision-sufficient views, provenance sufficiency, context compression under referential continuity, stale/superseded external state, and WorkingSet/WorkingView invariants.

## Programme C — Agent Action & Effect Semantics

**Question:** How does an Agent proposal become a bounded external operation, and how must intent, authority, admission, execution, effect, evidence and semantic outcome remain separated?

Primary existing substrate:

- Family C — Action, Control, Selection & Prospective Execution.
- HaF6,7,8,24,36,50,57,61.
- Runtime bridge for physical realization.
- Normative bridge for externally grounded authorization/admissibility where applicable.

Established basis:

- ToolIntent != PhysicalEffect != SemanticSuccess.
- Selection != authorization != dispatch != effect != result.
- lifecycle roles cannot be flattened into one success/failure state.
- prospective plan validity and control position are change-relative.

High-value open questions include delayed/partial/irreversible effects, side-effect attribution, compensating action, duplicate-effect hazards, observation gaps between effect and receipt, authority changes during execution, and composition of concurrent operational effects.

## Programme D — Operational Identity & Recovery

**Question:** What makes an Agent operation the same operation across time, interruption, migration, reconstruction and branching, and what constitutes a valid continuation after failure?

Primary existing substrate:

- Family I — Operational Identity & Orchestration.
- HaF52,53,55,58,59,60.
- Family C HaF61 control position.
- Family A HaF51/54/56 reference, placement and exposure.
- Entire HaF51–HaF61 Operational Spine as a cross-family view.

Established basis:

- TaskEpisode != Host Task != Runtime Job.
- RunEpisode != process != conversation != Host Task lifetime.
- Invocation lineage carries semantic relations that chronology alone cannot recover.
- reproduction contract != deterministic replay guarantee.
- operational control position is first-class.

This is the current **highest-information deepening candidate**, but it is not automatically the next selected campaign.

High-value open questions include Run identity equivalence, Recovery Equivalence, branch/divergence identity, provider/model migration, process restart, partial replay, ContextFrame reconstruction, unresolved Invocation recovery, and cross-locus Run migration.

## Programme E — Accountability & Assurance

**Question:** How can an Agent operation produce bounded, contestable and reproducible claims about what was attempted, realized, observed and concluded without turning evidence into external truth?

Primary existing substrate:

- Family D — Evaluation, Evidence, Explanation & Assurance.
- HaF10,23,27,28,29,31,32,33,34.
- Family I HaF58 Result attribution and HaF59 Invocation lineage.
- Engineering Consumption such as Run Receipt / CompletionProposal as downstream exemplars only.

Established basis:

- evidence dependency/common cause matters; artifact count is not corroboration count.
- Result must be attributed to the semantic object/layer that produced it.
- CompletionProposal != Host/caller/domain completion.
- explanation, contestability, lifecycle assurance and responsibility attribution are typed, claim-relative structures.

High-value open questions include operational accountability graphs, evidence sufficiency, cross-owner claim composition, contestability after environment change, responsibility across multi-Agent chains, and reproduction standards for non-replayable external reality.

# Bridge programmes

Bridge programmes study interfaces while preserving external semantic ownership. They are not additional Foundation programmes.

## B-Runtime — Invocation / Realization

Harness owns intent, selection, Invocation lineage and result attribution. Runtime owns Workspace/Job/Attempt/process and physical-execution truth.

## B-Host — Run / Durable Task Continuity

Harness owns bounded Run/TaskEpisode continuity. Host owns durable Host Task continuity. `CompletionProposal != Host Task completion`.

## B-Network — Capability Exposure / Cross-Locus Realization

Harness consumes and exposes remote operational capabilities; Network owns cross-locus reachability/realization/substrate truth.

## B-Normative — Authority Mediation

Harness may carry permission/commitment/policy/process state; Ordivon Normative owns constitutive/normative admission and consequence semantics.

## B-Human — Interaction Mediation

Harness owns externalized interaction/control/evidence mediation; Human owns human-native cognition, motivation and social-human reality.

## B-World/Domain — Observation / Effect Referents

Harness binds observations, claims and results to external referents; World and specialist domain owners retain target-world/domain truth.

## B-Computing — Computational Description / Capability Semantics

Harness may expose and invoke computational descriptions/capabilities; SCD, Computational Possibility and other Computing owners retain the corresponding semantic/computability truth.

# Programme selection rule

The programme map is not a queue. A new campaign must be selected by information gain, destructive-test value, unresolved architectural pressure, Engineering Consumption feedback and cross-owner significance. No programme may create HaF62 merely by being selected.
