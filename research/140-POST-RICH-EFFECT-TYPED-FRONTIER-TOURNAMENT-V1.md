## 4. Candidate C2 — Campaign-5 provider / locus / internalization OPUR

This candidate must be split; readiness is not uniform.

### C2-P — provider-route preservation under first-class ProviderUsePolicy

#### Direct expressibility

**HIGH for a bounded U.** `HarnessProviderUsePolicy` is a real first-class use contract over exact restricted input refs and exact allowed Provider/Adapter/Model routes.

A narrow direct branch can define configurations by existing product objects:

- B0 = Run Contract using allowed route R0 under exact policy U;
- B1 = Run Contract using a different route R1 that is also explicitly admitted by the same exact U;
- B2 = Run Contract using an unlisted route R2 under that same U.

The branch need not implement generic `Preserves_U`. It can directly test whether the concrete U-required obligations survive the route change.

#### Destructive testability

**VERY HIGH.** Prebound falsifiers include:

- B1 route change is incorrectly rejected solely because Provider identity changed despite exact U admission;
- B2 unlisted route reaches Provider factory or creates durable Run state before rejection;
- policy reference can be swapped independently from exact contract binding;
- restricted input digest can change while preservation is still claimed;
- route admission silently widens across reconfiguration;
- reverse direction is assumed without separately checking U.

#### Information gain

**HIGH.** This directly attacks Campaign-5 T10/T11 style provider substitution pressure with an actual use-policy surface that did not exist as the Campaign-5 primitive relation.

#### Owner boundary

**CLEAN.** Harness owns policy/route admission. Provider semantic quality remains provider/domain-owned. No Network claim is required for the provider-route-only branch.

#### Fixture-semantic risk

**LOW for exact route/use-policy preservation**, provided the branch claims only preservation of the policy's explicit obligations and does not promote this to universal provider implementation equivalence.

#### Existing real surface

**YES.** Public product plus current GVA4 policy tests already demonstrate exact fail-closed mechanics.

#### Engineering leverage

**HIGH.** This tests whether one explicit data-use/route obligation survives reconfiguration without creating a generic reconfiguration engine.

### C2-L — locus / Network migration

#### Direct expressibility

**PARTIAL / currently insufficient for transition proof.** Workstation supplies real current generation/capability/health facts, but current observed anchor/profile are unavailable/unknown and no exact before→after migration pair is present.

#### Destructive value

High once two owner-grounded loci/generations can be compared under one explicit U.

#### Disposition

**DEFER direct locus transition dogfood.** Retain the current unavailable/unknown owner observations as negative pressure, not a fabricated transition.

### C2-I — internalization/externalization

No current first-class transition relation or real selected cut-movement trajectory exists. **DEFER.**

### C2 overall disposition

**SELECT the narrow provider-route sub-branch only.** Do not claim general Campaign-5 OPUR closure.
