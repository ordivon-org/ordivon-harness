# 05 — HARNESS PROJECT CONSTITUTION v1

**Project identity:** Harness  
**Research subtitle:** Agent Operational Mediation  
**Status:** project constitution v1  
**Foundation baseline:** HaF0–HaF61 frozen; HaF62 UNKNOWN / NOT SELECTED / NOT ADMITTED

## 1. Project referent

Harness studies the boundary-relative structures by which an Agent receives externally grounded state, forms bounded operational context and candidate intent, receives capability exposure and authority, invokes external realization, attributes resulting evidence/effects/results, and preserves operational identity and continuity without acquiring semantic ownership of the mediated external reality.

The project therefore studies **Agent operational mediation**, not a particular Agent SDK, tool protocol, provider API, Runtime implementation, workflow product, database schema, or programming-language object model.

## 2. Canonical owner contract

Harness owns bounded, cut-relative Agent Run mediation: Agent-facing reference, representation, context, capability exposure, selection/control, Invocation, evidence/result attribution, Run identity, and related operational continuity structures.

Harness does **not** acquire the truth owned by systems it mediates. In particular:

- Runtime retains Workspace / Job / Attempt / process and physical-execution truth.
- Host retains durable Host Task continuity plus Host Journal/CAS/fencing/handoff authority.
- Network retains cross-locus capability, transport/path/service and reachability-realization truth.
- Ordivon Normative retains constitutive/normative admission, consequence and transformation semantics.
- Human retains human-native cognition, motivation, phenomenology and social-human structures.
- World/Reality and specialist owners retain target-world/domain truth.
- SCD, Computational Possibility and other Computing owners retain their corresponding computational semantic/computability truths.

A bridge may be deletion-essential to Harness mediation while remaining dependent on another owner's truth.

## 3. Constitutional commitments

### H-C1 — Cut-relative responsibility

Harness responsibility is defined relative to an explicit Agent–External operational cut. Objects do not become intrinsically “Harness objects” merely because an Agent touches them.

### H-C2 — Mediation without annexation

Representation, storage, invocation, evidence, authority carriage or interface possession never transfers external semantic ownership into Harness.

### H-C3 — Typed operational distinctions

Harness must preserve materially different operational roles rather than flatten them for implementation convenience. In particular:

`Proposal != Eligibility != Authorization != Admission != Selection != Dispatch != Execution != Effect != Result != SemanticSuccess`.

No universal mandatory pipeline is implied; the invariant is preservation of distinctions where the roles differ.

### H-C4 — Operational identity is first-class

Reference, TaskEpisode, OperationalContextFrame, Invocation lineage, RunEpisode, Result attribution and ControlFlowState are semantic operational objects, not merely log labels, process IDs or UI statuses.

### H-C5 — Evidence is not truth

`Representation != Truth`, `Evidence != Truth`, `Observation != Retention`, and `History != Cognition`. Harness may preserve and qualify claims/evidence without becoming their external authority.

### H-C6 — Research precedes implementation ontology

Python classes, schemas, CLI flags, database tables, provider protocols, current product architecture and tests are Engineering Consumption or experimental evidence. They cannot retroactively create, rename, merge, reopen or prove a Harness Foundation.

### H-C7 — Simple affordance, deep semantics

Agent-facing operations should remain easy to use where possible, but semantic complexity must be **submerged rather than deleted**. Ease of invocation is not permission to erase authority, provenance, effect, attribution, lifecycle or owner distinctions.

### H-C8 — Foundation expansion requires destructive pressure

HaF62 or any future Foundation requires a concrete `FoundationReopenCondition` or fresh whole-referent evidence showing coherent, deletion-essential Harness-native responsibility not absorbable by HaF0–HaF61 plus owner-preserving bridges. Sequential numbering, implementation novelty, symmetry or terminology are insufficient.

## 4. Research / engineering relation

Harness Research and Ordivon Harness engineering form a bounded evidence loop:

`Research distinctions -> Engineering Consumption -> dogfood/failure/counterexample evidence -> Research evaluation`.

The reverse path carries **evidence/falsifiers**, not implementation authority. A working implementation may falsify an assumption or expose a missing distinction; it does not define the research ontology by existence alone.
