## 2. Post-Campaign-4 dependency delta

Four preservation families are now explicit:

- **Identity obligations:** Run/continuation/branch/recovery relations;
- **Context obligations:** validity/currentness/sufficiency/equivalence under bounded use;
- **Realization obligations:** dispatch standing, realization claim Q, reconciliation and redispatch constraints;
- **Accountability obligations:** OCSS claim-support, dependency, unknown/counterevidence, attribution and bounded reproduction.

This makes a previously vague frontier sharply testable:

> If the Agent/external cut, process, provider, loop morphology, capability placement, exposure surface or locus changes, what must be preserved so that a bounded operational use may still treat the post-change configuration as equivalent/substitutable — and which changes instead create a new Run, new Context obligation, new authority exposure, new realization risk or new accountability state?

## 4. Candidate comparison

### C1 — Boundary Reconfiguration Equivalence

**Programme home:** A — Agent–External Boundary Semantics, with D/B/C/E preservation obligations.

**Information gain:** very high. It is now the first frontier that must preserve all four completed campaign relation families under structural change.

**Destructive-testability:** very high. Counterexamples include same implementation with changed authority, same outputs with stale Context, changed loop morphology with preserved authority, successor attempt with changed Run identity, process/locus migration with unresolved effects, exposure expansion, hidden evidence loss, and boundary changes that preserve visible behavior but alter ownership/authority.

**Engineering evidence:** meaningful current surfaces exist across morphology, successor attempts, exact prior-receipt adoption, tool-authority preservation and unknown-effect stopping.

**Owner-boundary risk:** high but controllable if equivalence is use-contract/preservation-relative rather than “same architecture” or “same world behavior”.

**Synthesis leverage:** highest. It directly composes Campaigns 1–4.

Decision: strongest current Campaign-5 candidate.

Boundary-equivalence criteria would reduce this search space by clarifying what survives a moved/split cut before federation multiplies cuts.

## Operational Preservation Under Cut, Placement, Exposure & Morphology Change

Programme home: **A — Agent–External Boundary Semantics**, consuming D/B/C/E campaign results.

### Bounded purpose

Derive and destructively test a technology-neutral criterion for when a change in operational boundary/configuration may be treated as equivalent or substitutable for a bounded use despite changes in implementation, process, provider, morphology, placement, exposure or locus.

### Explicit non-goals

Campaign 5 will not:

- define global behavioral equivalence of Agents/models;
- require identical implementation/bytes/configuration;
- require same Run identity for every equivalent substitution;
- treat same output as proof of semantic equivalence;
- annex Runtime process/resource truth;
- annex Network reachability/topology truth;
- annex Normative legitimacy of authority transfer;
- solve Multi-Agent federation;
- create HaF62.

## 6. Required Campaign-5 destructive dimensions

The Charter must prebind at least:

- same implementation but expanded authority/exposure;
- different implementation/morphology with preserved tool authority and use obligations;
- successor attempt changes loop identity while explicitly adopting prior evidence;
- same visible result but changed Context/currentness obligations;
- process restart with preserved Run vs successor Run distinction;
- provider replacement with equivalent requested capability but changed evidence/uncertainty behavior;
- locus migration where Network reachability changes but Harness use contract may or may not survive;
- capability internalization/externalization that changes the Agent/external cut;
- unresolved prior realization standing carried across reconfiguration;
- accountability evidence lost or role-aliased during reconfiguration;
- authority revoked/expanded during reconfiguration;
- stale selection reused after available-profile/exposure set changes;
- same Context bytes under changed authority/currentness;
- behaviorally identical outputs from semantically non-equivalent configurations;
- different outputs under a bounded contract that does not require outcome identity.
