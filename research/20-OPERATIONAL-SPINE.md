# 20 — OPERATIONAL SPINE

HaF51–HaF61 form a **cross-family Operational Spine view**. This is a second-stage operational navigation surface, not a new Foundation tier, not a roadmap, and not evidence that later HaFs are more fundamental than HaF0–HaF50.

| Order | Identity | Operational role | Primary family |
|---|---|---|---|
| 1 | HaF51 | Reference / naming / binding / resolution mediation | A |
| 2 | HaF52 | TaskEpisode identity and composition | I |
| 3 | HaF53 | OperationalContextFrame and scope continuity | I |
| 4 | HaF54 | Functional placement / migration / boundary reconfiguration | A |
| 5 | HaF55 | Execution reproduction / replay / branching contract | I |
| 6 | HaF56 | Boundary interaction exposure surface | A |
| 7 | HaF57 | Operational selection disposition | C |
| 8 | HaF58 | Result attribution | I |
| 9 | HaF59 | Invocation lineage | I |
| 10 | HaF60 | Bounded operational Run episode | I |
| 11 | HaF61 | Run-relative control-flow/control-position state | C |

Canonical spine shorthand:

`Reference → Task → Context → FunctionalPlacement → Reproduction → BoundaryExposure → SelectionDisposition → ResultAttribution → InvocationLineage → RunEpisode → ControlFlowState`

Important separations:

- Reference != referent truth.
- TaskEpisode != Host Task != Runtime Job.
- Context != all retained history != hidden model cognition.
- Reproduction contract != deterministic replay guarantee.
- Boundary exposure != capability ownership.
- Selection disposition != normative authorization != physical dispatch.
- Result attribution != semantic success != domain acceptance.
- Invocation != Runtime process/attempt.
- RunEpisode != Host Task lifetime.
- ControlFlowState != universal workflow/state-machine ontology.

The Operational Spine crosses Families A, C and I and exists only as a consumption/navigation view over the exact HaF identities.
