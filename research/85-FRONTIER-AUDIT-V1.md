## 2. ESTABLISHED architectural substrate

The following are strong enough to function as current project constraints or derived laws at the present evidence frontier:

- cut-relative Harness responsibility and mediation-without-annexation;
- separation of external truth ownership from Harness representation/evidence;
- `Observation != Retention`, `History != Cognition`, and provenance/scope-relative epistemic state;
- typed action/control distinctions including `ToolIntent != PhysicalEffect != SemanticSuccess`;
- non-flattening of materially distinct lifecycle roles;
- first-class operational identity vocabulary: Reference, TaskEpisode, ContextFrame, Invocation lineage, Result attribution, RunEpisode and ControlFlowState;
- TaskEpisode / RunEpisode separation from Host Task and Runtime Job/Attempt;
- reproduction-contract separation from deterministic replay;
- result attribution and CompletionProposal separation from caller/domain/Host completion;
- cross-owner firewalls for Runtime, Host, Network, Normative, Human, World/domain and Computing truths;
- Research -> Engineering Consumption directionality with implementation returning evidence/falsifiers rather than ontology authority.

## 3. PARTIALLY ESTABLISHED / high-information deepening

These areas have substantial HaF substrate but lack a sufficiently sharp project-level theory, equivalence criterion, destructive campaign or composition law.

### P-D1 — Run Identity Equivalence

Known: RunEpisode is distinct from process/conversation/Host Task and has lineage/context/control structure.

Missing: necessary/sufficient criteria for preserving or splitting Run identity across provider/model change, process restart, context reconstruction, migration, branching and divergent replay.

### P-D2 — Recovery Equivalence

Known: ControlFlowState, Invocation lineage and reproduction contracts are first-class.

Missing: a criterion for when recovered operational state `S'` is a valid continuation of pre-failure state `S`, especially around unresolved/possibly-effected Invocations.

### P-B1 — Context Equivalence and Sufficiency

Known: ContextFrame, WorkingSet/WorkingView-style representation distinctions, provenance and decision-sufficient-view pressure exist.

Missing: when two different operational contexts are equivalent for a bounded TaskEpisode, what information may be removed safely, and which reference/provenance/authority changes invalidate equivalence.

### P-C1 — Rich Effect Semantics

Known: intent, dispatch, physical effect, evidence and semantic success are distinct.

Missing: general treatment of delayed, partial, irreversible, unobserved, duplicated, compensating and interacting effects.

### P-E1 — Operational Accountability Graph

Known: evidence dependency, explanation, contestability, responsibility and Result attribution are established structures.

Missing: a minimal cross-layer graph that can reconstruct why an operational claim was made while preserving external owner authority.

### P-A1 — Boundary Reconfiguration Equivalence

Known: cut relativity, functional placement and boundary exposure are established.

Missing: conditions under which migration/internalization/externalization changes implementation placement without changing Harness semantics, versus when the operational cut has materially changed.

## 4. UNTESTED / lightly tested frontiers

These are plausible project-level frontiers but must not be treated as pre-admitted theory:

- Multi-Agent / federated Run identity across independently controlled Harness loci.
- Authority/exposure changes during an in-flight Invocation.
- Cross-locus Run migration with Network/Runtime truth kept owner-preserving.
- Context equivalence across materially different models/providers.
- Recovery after effect occurred but receipt/evidence was lost.
- Recovery after receipt existed but WorkingSet/Context update was lost.
- Concurrent Invocations whose effects interfere or invalidate each other's preconditions.
- Responsibility attribution through Agent -> Harness -> Runtime -> external-service chains with partial observability.
- Reproduction standards for operations over non-replayable external environments.
- Whether operationally equivalent capability surfaces can be defined independently of implementation/API identity.
- Whether a generic minimal Agent-operation model survives non-LLM agents, long-running autonomous controllers and mixed-initiative human/Agent systems.

4. Rich Effect Semantics;

Selection should compare deletion-essential novelty, destructive-testability, cross-owner impact, engineering leverage, and ability to falsify current architecture.
