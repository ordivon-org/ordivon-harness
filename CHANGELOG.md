All user-visible changes to Ordivon Harness are recorded here. Release and compatibility rules are defined in `docs/RELEASES.md`.

### Changed

- `candidate_completed` now means bounded Run completion rather than epistemic closure: conclusions may retain honest unresolved unknowns, and new `IndependentCompletionProposal` v2 records them while still reading v1 proposals as having no recorded unknowns;
- the recommended `ordivon_harness.api` facade is now closed over basic Run Contract authoring and the built-in execution paths: DeepSeek settings/adapter, no-Tool and search capability digests, bound/correlation references, execution/runtime references, and Runtime error-contract types are available without dropping to `ordivon_harness.core`;
- no-Tool Runs may bind `maxToolCalls=0`; model, observation, wall-time and token budgets remain positive and Tool capability is still controlled only by the Contract Tool catalog/grant;
- Run privacy is now authoritative over Harness-managed durable content: default `metadata-only` continuity retains execution identities/digests/fences without exact model transcript, Provider result, Tool observation, dynamic Provider-error detail, Trace payload or terminal conclusion/proposal content; exact cross-process content replay requires explicit `bounded-private-content` authority, while completed-effect fencing still prevents redispatch when bytes were intentionally not retained;
- the mature Agent Loop now separates canonical Run history, durable Agent-selected WorkingSet, transient complete Tool exchanges and per-turn execution control: external/domain discovery may expose candidates without silently selecting them, projected Tool evidence retains the Provider-authored assistant `toolCalls` message plus its exact bound observations, raw discovered content must be privacy-aware materialized before it can become an exact pin, and Agent-authored successor transitions bind both the source WorkingSet and the exact effective model view they came from; DeepSeek also receives the current remaining budget and admitted Runtime Tool names as execution-control metadata rather than task Context; Harness still owns no Context discovery/ranking/RAG/Memory policy and these cognition execution seams remain outside the recommended public facade;
- observation-only/no-progress thresholds and exhausted Tool budgets now close external observation capability before the next Agent turn instead of immediately synthesizing a Harness-authored epistemic conclusion; an Agent may conclude or use an admitted cognition transition over the evidence already seen, while attempts to reuse a now-unavailable historical Runtime Tool are locally model-correctable with zero physical dispatch and consume correction budget rather than exceeding the external Tool budget;
- Tool-bearing WorkingView Runs now recover attempt-local transient cognition across both hard Tool-effect recovery and ordinary clean pause/resume: Continuity derives the current WorkingSet-attempt boundary from Journal order, reconstructs complete Provider-authored Tool exchanges from exact completed Provider results plus terminal Tool intent/receipt/Observation evidence, reconciles already-completed effects without redispatch, excludes predecessor-attempt exchanges after a WorkingSet transition, and fails closed when exact Tool content was not authorized; no new SQLite schema or generic conversation store was added;
- durable knowledge retention is now explicitly modeled as Agent WorkingSet selection rather than a new Memory/Promotion subsystem: materialized source bytes may exist without cognition authority, an Agent promotes a source by explicitly including its exact pin in the successor committed WorkingSet, later omission drops that current cognition even while CAS bytes remain, and materialized-but-unselected sources are never automatically injected; structural Tool privacy remains distinct from semantic taint tracking, so Harness does not pretend a promotion-specific provenance tag can infer whether ordinary text was derived from Tool data;
- an opt-in Agent cognition control can now inspect a bounded reverse-chronological catalog of earlier **committed** WorkingSet identities and exact pins, allowing a dropped source to be recalled through the existing Agent-owned transition path without semantic Memory search, source-content disclosure, ranking, Runtime dispatch or external Tool budget; materialized-but-never-selected sources are excluded, pagination is event-sequence bounded, forged local history results are rejected by deterministic Journal replay before the next Provider dispatch, clean-pause replay uses the existing attempt-local exchange reconstruction, and the Tool-shaped Provider transcript requires both model- and Tool-content authority;
- cognition-attempt identity is now separated from progress authority: a successor attempt with the same exact WorkingSet pins remains lawful and still discards predecessor attempt-local Tool cognition, but it no longer resets observation/no-progress counters or reopens a closed soft external-effect gate; exact selected-pin changes remain structural cognition progress and may reset the soft gate, hard Tool-call budget stays global, and fresh-process resume reconstructs the soft gate from durable counters;
- projected `needs_input` resume now has a caller-owned cognition ingress distinct from WorkingSet selection and Tool exchange: exact plain caller `user` messages become model-visible without being auto-materialized or auto-selected, persist across Agent WorkingSet transitions until the next `needs_input` Snapshot, interleave deterministically with pre/post-caller Tool exchanges by Journal order, reset soft progress only because the Agent actually sees new input, survive Tool snapshots and Provider response loss without caller resend, and are revalidated against Snapshot/RunState authority before dispatch so forged or system/assistant/Tool-shaped resume overlays fail closed; this path requires model-content authority but not Tool-content authority and adds no SQLite schema or generic conversation store;
- an opt-in Agent caller-ingress promotion action can now turn an exact subset of the current caller interaction into durable WorkingSet cognition without giving Harness or the caller selection authority: the Agent chooses exact currently-promotable caller indexes plus a new slot, Harness derives and materializes the exact bytes from Snapshot/Provider provenance and mechanically extends the current selected pins, Provider response-loss replay applies the promotion exactly once, and model-only privacy is sufficient when no Tool channel is present; real DeepSeek experiments rejected an earlier design that required restating hidden pin identities, then exposed duplicate-projection and hidden-provenance friction, so the final boundary uses provenance-aware caller-overlay suppression, explicit `AgentTurnRequest` caller-ingress references, and dynamic promotion capability withdrawal when no promotable ingress remains; no generic Memory service, semantic summarization, ranking, Conversation Store or SQLite schema was added;
- current durable cognition is now exactly addressable to transition-capable Agents without adding a supersession/Memory-update primitive: projected requests may carry each current WorkingSet pin plus its exact source-message range, DeepSeek exposes those identities as `workingSetSelection` only when the transition surface is granted, and Continuity recomputes the mapping from the committed WorkingSet/source objects before dispatch so forged pins or ranges fail closed; real DeepSeek correction experiments then used the existing transition action to turn `[task, RED-9, GREEN-42]` into `[task, GREEN-42]` in one Provider turn while RED-9 remained in committed cognition history, proving that correction is promotion plus ordinary Agent-owned selection rather than Harness-authored semantic supersession; the transition Tool description now also states that same-pin transitions are attempt resets, not progress or a way to wait for caller input;
- **Breaking pre-1.0 H3:** Ordivon Harness is now a single independent Agent Run product line. The SQLite Harness Journal/CAS is the only current Run writer and `HarnessRunContract` is the only current caller/execution contract.
- the CLI has one `--state-root` meaning and only independent `capabilities`, Run/recovery, and `store-*` commands; the historical `host` namespace and all `cutover-*` commands were removed;
- the package root now mirrors `ordivon_harness.api` plus `package_version` instead of resolving historical lazy compatibility exports;
- the built wheel and repository dependency graph contain only the exact Ordivon Protocol dependency. There is no `host` extra, Host development dependency, or Host pin.

### Removed

- `HarnessHost`, Host-backed `HarnessRunner`, `HostHarnessRunStore`, TaskContract/Assignment/native-Run compatibility objects, `_host_compat`, Host history/handoff/recovery controllers, cutover state, and Host-backed CLI/configuration paths;

- frozen pre-migration persistence inventory/checks whose object/event set described the deleted Host-backed writer;
- compatibility aliases and decoders whose only purpose was preserving the removed Host-backed product line. Historical evidence receipts remain immutable evidence of the implementation revisions they bind.

### Retained

- independent Provider Call claim/dispatch/completion/failure durability, response-loss replay and UNKNOWN recovery;
- independent Tool-step intent/fence/receipt continuity and caller-supplied Runtime bridges;
- bounded Agent loop, pause/resume snapshots, Trace, Run Receipt, Recovery Assessment and CompletionProposal;
- repository-repair read/edit bridges and the Host-free duck-typed `host_external_adapter` integration module.

### Fixed

- H2 lifecycle-bound phase-A Provider failures now preserve `AgentTurnFailureCode` and dispatch safety: an Adapter-proven `pre_dispatch_safe` failure remains not dispatched and maps to its specific Provider stop code instead of being inflated to `provider_state_unknown`; ambiguous dispatch remains UNKNOWN;
- DeepSeek turns that simultaneously request ordinary Tools and `submit_run_conclusion` no longer become Harness failures: the mixed turn is rejected before physical Tool execution and returned through the existing model-correction path so the Agent can choose one action on the next turn;
- the DeepSeek conclusion Tool now describes caller/domain verification rather than the removed Host-backed verification model, and Standalone execution fails closed when a structured completion Contract is not bound by the executing Adapter;
- Quick Start now includes a caller-authored Contract construction path, the DeepSeek 8,192-token completion-ceiling preflight behavior, Runtime error-translation requirements for Tool-bearing callers, and a wheel-verification command that passes the actual wheel path;
- canonical security, data/privacy, verification and domain-Tool guidance now describe the independent Harness Journal/CAS and current Host-free Run API instead of removed Host-backed Assignment/Runner persistence; documentation checks reject those stale current claims;
- concurrent same-digest CAS publication now preserves one immutable published inode and tolerates publication-only `ctime` movement without weakening canonical digest, inode, size, mtime, mode, or no-follow checks;
- SQLite database/WAL/SHM hardening now happens outside active SQLite lock ownership, preventing hardening descriptors from disturbing process-scoped locks under multi-process Store use;
- Continuity, Provider-claim, and terminal-recording execution owners are process-instance unique, so idempotent durable dispatch admission cannot be consumed as duplicate physical Provider or Runtime execution;
- ordinary Store open validates global physical state without replaying every unrelated Run; the target Run is fully history-validated when Continuity opens and full Doctor remains authority-wide.

### Verification

- current deterministic suite runs only the independent product line and preserves Provider/Tool response-loss, fencing, recovery and restart coverage;
- isolated wheel verification requires one Protocol dependency, no Host installation, no Host-backed modules, one independent package-root API, and 14 independent CLI commands;
- `check_dependencies.py`, `check_docs.py` and repository-boundary tests fail if Host imports/dependencies or compatibility product files reappear.
